# 数值漂移：参考、运算语义与验证

用于跨框架、编译器、精度或执行方式变化后的数值排查。验收标准沿用[数值验证](numerical-validation.md)。按当前差异选择相关方法；本页的算子和框架例子用于说明如何验证假设，不预设根因、实现方式或新增测试矩阵。

## 明确这次在比较什么

先确定用户选定的可执行参考、输入与比较量。权重保存格式不等于参考前向实现；模型标称 dtype 也不能完整描述实际运算。按问题需要核对源码／补丁、配置、权重映射、运行环境和实际加载路径，不仅依赖版本标签。

区分数学语义、具体浮点执行行为与验收标准。数学等价不保证逐位相同；中间 tensor 不同也未必违反只要求最终 Top1 的协议。更高精度可能改善数学误差，却不一定更接近指定的低精度参考。

若参考来自训练，单卡复现和原分布式训练应各自标明拓扑、物理形状与编译条件。局部模拟可以检验一个假设，不能自动替代整网或通信路径的验证。只补足本任务所需的参考身份；缺少加载环境不应靠修改模型算法掩盖。

## 沿数据流检查差异机制

从首个已观测到差异的边界向上游核对输入和状态。下游投影或 logits 不同可能只是传播结果；抽查位置相同不能代表全部输入相同。确认边界输入可比后，再判断其内部哪些因素需要隔离。

| 机制 | 需要核对的内容 |
|---|---|
| 数据与状态 | 输入 IDs／位置、mask、布局、权重映射、初始状态及更新边界 |
| 精度转换 | 参数保存与加载类型、forward 内转换、累加类型、中间 materialization、输出／状态写回 |
| 归约与表达式求值 | 分块及归约树、乘加融合、表达式重排、缩放与归一化的先后 |
| 执行选择 | 实际 kernel／算法、调度形状、并行拓扑、编译与 autotune 配置 |

这些因素可能独立存在，也可能相互作用。不将差异统一归为“浮点误差”，也不默认用补齐、升精度或重写 kernel 处理。先做能区分当前假设的对照，而非遍历整张表。

对精度敏感的路径，可记录“保存 → 加载 → 算子输入 → 累加／归约 → 中间值 → 写回”的类型与转换点。同一模块的不同参数可能遵循不同规则；从参数名、模型标称类型或单个保存 dtype 推导整段运算，证据不足。

对于编译执行，核对本次真正运行的代码及配置。相同源码在不同编译上下文或配置下可能采用不同求值方式；编译缓存中存在某个产物不证明它被使用。外部依赖或加载路径与预期不同，也应先确认实际前向身份。

## 让输入和观测保持可比

自回归序列出现首个不同 token 后，后续同一步号已不代表相同输入。诊断逐位置差异时固定比较前缀、位置和输出行；真实生成、状态推进等行为仍按约定用例单独验证。原始 argmax、采样变换后结果和完整生成序列分别说明。

怀疑参考自身波动时，选择同进程重复、独立启动或缓存条件对照。固定 seed 不代表算法／归约选择必然固定。参考漂移需要定位，不能据此宣称候选正确或自行更换验收口径。

抓取张量保留原 dtype、有效范围和原 shape/stride，避免抓取中的转换掩盖差异。转设备或复制后的布局未必等于原布局；记录原元数据。捕获输入按实际调用映射，不仅依赖源码中的变量名或参数顺序。

hook、同步、graph break 和独立编译可能改变被观察行为。检查诊断运行是否仍复现目标差异。独立算子回放若无法在原条件下复现整网捕获，就先说明回放差异；它仍可能支持局部对照，但不能直接用于归因原整网问题。

## 建立因果证据，再选择修复

有了可复现边界后，复用真实输入、权重、状态和布局，尽量一次只改变一个假设因素。强证据是该因素的不同取值能够复现两边差异，并在恢复原条件后重新出现；一次最终输出恢复不足以排除同时发生的其他变化。难以隔离时，保留尚未排除的因素。

| 证据 | 适用结论 |
|---|---|
| 源码中存在某种实现 | 提出机制假设；仍需确认实际执行与影响 |
| 实际捕获中输入可比、输出先不同 | 将差异定位到该观察边界，不一定已定位内部算子 |
| 受控对照复现并消除差异 | 确认已测条件下的因果机制 |
| 修复接入后完成约定回归 | 该源码在约定范围通过，不外推未测条件 |

区分“首个观测差异”与全网绝对首差；最终 logit 差距不能直接当作最初舍入误差。某算法配置影响输出，与为何选中了它，是两个需要不同证据的问题。Top1 margin 可辅助选诊断位置，但不自动形成允许误差。

依据实际原因选择修复：可能是接线、状态、参数加载、转换边界、运算次序或算法选择，不预设必须改 kernel。尽量局部表达已确认的语义，随后验证受影响的调用路径。需要兼容多个确有差异的参考时，可考虑明确的兼容配置；不因此要求每个模型都增加参考开关或按 checkpoint 名称分支。

## 兼容办法与性能优化分开交付

快速支持可以先采用已验证的兼容办法，注明适用范围、代价和未解决项。若本任务只要求适配，不将额外优化研究作为交付前提；若任务要求消除冗余，则需要用实际执行和性能证据说明冗余已减少。

补齐行数是其中一种案例：行局部算子可能因物理形状切换算法，导致有效输出不同。需先排除跨行归约、状态更新等语义变化，再比较原形状与实际有效工作量。两个大形状相同不证明更小形状相同，缩到另一个大桶也不必然完成有效行优化。

对这类问题，长期方向是保留所需数值行为、减少与有效工作量无关的计算，而不是持续扩大补齐。硬件 tile 对齐或真正的模型计算需求与兼容性冗余应区分；不能将所有 padding 都视为缺陷，也不能将历史通过形状视作所有模型的要求。

修复后的验证范围按当前验收与受影响兼容路径确定。局部回放、模型回归与性能测量分别支持不同结论；性能保持请求、调度、缓存及预热条件可比，见[性能对照](benchmarking.md)。

## 条件案例：怎样把具体经历转成可验证假设

下列例子说明检查方法，**不指定其他实现应采用哪种 dtype、顺序、归约配置或形状**。只有当前调用具有相应结构时才适用，修复方向以当前参考和证据为准。

| 场景条件／案例 | 可复用的判断方法 |
|---|---|
| 主参数以 FP32 保存，但某卷积 forward 转为激活 dtype | 分开核对保存与运算类型；不能把保存类型直接当作算子精度要求 |
| 归一化使用 `w + 1` 形式构造有效 gamma | 比较参数变换及其转换边界，再看归一化和后续投影；不推广为所有 NORM 都应有此加法或低精度舍入 |
| residual 与 RMS 被融合 | 核对融合前后中间值是否 materialize、返回残差被谁消费；不能统一要求保留 FP32 或统一要求先转低精度 |
| 平方和在不同归约／FMA 配置下不同 | 固定输入后观察部分和及实际执行配置，隔离归约与乘加次序；具体 block、warp 和 FMA 顺序不直接复用 |
| Self/Cross-MUDD 等多源混合模块 | 分开比较来源、权重、混合、归一化和写回；若混合值相同而归一化先不同，按证据缩小定位，不因模块名称重写整段 |
| 投影前归一化不同，投影输出随之不同 | 沿输入追踪首差，避免把下游可见差异直接归因给 GEMM |
| 单卡只改变物理行数，观察有效输出 | 结论限于形状对照；不能据此声称已验证完整分布式训练路径 |

原始案例的版本、输入、数值与通过结果保留在项目证据中。迁移经验时带走假设与验证方法，不直接带走固定参数和最终结论。状态相关差异另见[状态生命周期](stateful-inference.md)。
