# 数值漂移：参考前向、舍入与有效行计算

用于跨框架移植、编译器迁移、NORM/MUDD 融合、投影形状和循环模型的数值排查。验收定义沿用[数值验证](numerical-validation.md)；这里说明如何建立因果证据，不追加一套统一的验收矩阵。

## 快速适配与长期实现

为尽快支持一个参考，允许先用补齐行数、保留参考融合边界等兼容办法通过约定验收。说明触发范围、额外计算与显存成本，保留通过的版本作对照。若任务是快速交付，不把后续消除冗余的研究变成前置条件。

长期优化的目标是按本步实际有效 token／概念行计算，同时保留约定的数值行为。有效行不是整个历史长度或配置窗口；硬件 tile 必需的小范围对齐与匹配参考大矩阵的冗余补齐也应分开。缩到另一个固定大桶、裁掉输出但仍计算全部行，都不等于消除冗余。补齐能消除差异只提供形状敏感的线索，不能据此认定所有差异都来自行数。

归约、融合和舍入即使在同一形状下也可能不同。优先查真实执行的算子与数据流，选择局部修复；不机械提高所有精度，也不不断扩大“保险形状”。尚不能在有效行下满足约定时，明确保留临时路径及未解决原因，不宣称已完成有效行优化。

## 先确定可执行的参考

HF 格式说明权重如何保存，不能据此认定参考就是 HF 前向，也不能把训练框架 A 的导出权重直接视作框架 B 的数值参考。沿训练目录或交接记录核对源码提交／补丁、实际 config、checkpoint 导出映射、训练依赖和验收入口；移植加载器须核对参数覆盖、布局和未加载项。

区分以下对象：训练时的分布式执行、指定的单卡参考、交付推理实现。训练 SP/TP、物理长度、编译配置不同，结论须分别限定；模拟单算子形状不能当作真实 SP/TP 的通信与整网验收。

镜像标签、冻结源码和 Python 包版本各自只覆盖一层身份。外部 PYTHONPATH、挂载的 FLA／自定义算子和共享库可能改变实际前向；检查实际 import 路径、运行时版本和相关包／源码摘要。缺 cuDNN 或解释器路径错误先按加载环境排查，不用改模型算法掩盖。复现所需挂载应从启动脚本与实际 import 汇总，避免每缺一项才临时更换依赖；无需全量复制无关环境。

## 为敏感算子记下精度流

“BF16 模型”不能描述每一步计算。沿具体调用记录这些位置，必要时用一张小表，而非给整个模型贴一个 dtype 标签：

| 位置 | 要核对什么 |
|---|---|
| checkpoint／主参数 | 导出 dtype、训练精度例外、参数重命名后的匹配规则 |
| 加载后的参数／状态 | 加载器是否统一转换、重载是否保留原值、缓存状态类型 |
| 算子输入 | forward 内显式 cast、autocast、参数与激活组合 |
| 累加与归约 | accumulator 类型、归约树、分块、FMA、算法选择 |
| 中间结果与写回 | 融合中保留的类型、何处 materialize／cast、输出和持久状态类型 |

例如，主权重保存为 FP32，但卷积 forward 显式转成激活 dtype 时，不能据保存类型把卷积改成 FP32 计算；同模块的衰减参数可能确实保留 FP32。分别核对，不将一组参数一概而论。更高精度不保证与指定参考更一致。

## NORM、MUDD 与融合：逐个定位舍入边界

把 NORM 前后的残差、混合、投影一起画成数据流。以下是需要证据区分的机制，不是所有模型应采用的固定计算顺序：

| 差异候选 | 最小对照与观测点 |
|---|---|
| 有效 gamma 的构造 | 固定 x、w，比较 `cast_low(w + 1)` 与保留高精度的 `w + 1`；捕获有效 gamma、NORM 输出及下一投影 |
| residual + RMS 融合 | 固定两路输入，比较残差和先落到 BF16 再归一化，或保留 FP32 直接进入 RMS；同时检查残差返回值及其后续消费者 |
| 平方和归约 | 固定输入、shape、epsilon 和 dtype，检查 lane 部分和、归约树、block／warp 配置、mean 与 rsqrt；相同 FP32 累加类型仍可能有不同归约结果 |
| FMA／表达式重排 | 分别观察平方、乘加与部分和；显式相乘后相加和融合乘加的舍入边界不同，编译器可能改变哪一项先舍入 |
| 归一化后的缩放 | 检查 rsqrt、gamma、路由权重及其乘法先后，在哪一步转回低精度；相同最终 dtype 不代表中间顺序相同 |
| 多源混合／Self、Cross 路由 | 先比各源和权重，再比混合值、归一化、写回；mixed 已一致而平方和先不同，应查 NORM，不能只因模块名包含 MUDD 就重写路由 |

从整网捕获到的 FC1 输出不同，不表示 FC1 GEMM 是根因；输入 NORM 可能已不同。某些抽查位置一致也不能代表整段前缀一致。前置输入有差异时，先追输入；前置输入全部一致后，才对局部算子作因果归因。

同样的 Python 表达式跨 Torch／Triton 版本，或跨独立编译与整图融合，可能实际执行不同的归约和 FMA。核对本次真正运行的生成代码及 launch 参数，不能从编译缓存里碰巧找到一个文件就认定它被执行。不把历史某个 block 大小、warp 数或 FMA 次序固化为其他模型的通用规则。

## 固定前缀，验证观测本身

自由生成一旦出现首个不同 token，后续相同步号已不是相同输入。逐位置比较应明确同一 prompt IDs、同一后缀／teacher-forced 历史、position 与目标 logit 行；另用约定的真实生成测试验证状态推进。比较的是原始 argmax 还是采样变换后的结果，也要写明。

若怀疑参考漂移，区分同进程重复、独立启动和编译缓存复用。seed 固定不等于归约／autotune 选择固定。参考自己不稳定既不证明候选正确，也不自动允许换参考；先保存各次输出与实际配置，说明受影响的验收条件。

抓取 tensor 时保留原 dtype、有效范围及原 shape/stride；不要为了节省空间统一转 BF16，再宣称 FP32 中间值相同。转 CPU／clone 后的布局未必等于原布局，原元数据须单独记录。映射捕获输入按实际调用顺序，不能想当然套 Python 参数或 alpha/beta 的顺序。

hook、graph break、局部 compile、同步和额外输出都可能改变融合或算法选择。检查加观测后的目标输出仍复现原失败；如果观察版本改变了结果，明确它只能辅助诊断。独立算子回放先验证同形状能否复现整网捕获，不能把回放上下文变化归因到待测变量。

## 用单变量回放证明原因

1. 在已有有效捕获边界中找到最早差异，必要时缩到模块内算子。记录已检查范围，不把“首个观测差异”称为全网绝对首差。
2. 复用该位置真实输入、权重、状态和布局。先确认基线回放匹配捕获输出，再一次改变一个因素：cast 边界、归约配置、融合、行数或算法。
3. 用候选因素的两个取值复现两边输出；恢复原值再次复现。只看到最终 Top1 恢复，尚不足以排除其他同时改动的因素。
4. 将已证实规则局部接入，再回到相同前缀的模型输出、受影响的批量／连续请求路径验证。局部相等不代替整网验收，中间张量有差异也不自动违反只要求 Top1 的协议。

建议按证据强度写结论：

| 证据 | 能说到哪里 |
|---|---|
| 源码里存在一种 cast／归约写法 | 待核对的机制，尚未证明本次调用执行了它 |
| 实际执行捕获中输入相同、输出先不同 | 差异定位到该捕获边界，仍可能包含多个算子 |
| 单变量回放重现并消除两边差异 | 在固定输入与配置下确认因果机制 |
| 接入后完成约定回归 | 该源码及约定范围通过，不能外推未测长度／拓扑 |

最终 logit 差距和 Top1 margin 可用于挑选诊断位置，不能当作首次舍入误差大小，也不自行形成“允许分差”。归约布局已被证明影响输出，不代表启动时为何选中某布局也已证明；机制与选择原因分别记录。

## 形状敏感：消除冗余要测实际有效行

分别记录逻辑请求长度、训练／参考物理长度、引擎 max_model_len、调度 token budget，以及文本／概念算子的有效行与实际执行行。这些量不是同一个开关。上下文容量增大不应被直接解释成所有投影也按更大窗口计算。

行局部的矩阵乘在数学上不应受其他填充行影响，但物理形状可能切换 GEMM 算法、分块或累加路径。先确认算子没有跨行归约、路由容量或状态更新等语义耦合，且 padding 不被当成有效 token，再做形状对照。

两个大桶相等不能推出缩到 B1／真实 batch 行数仍相等；单卡增大物理行数也不能证明训练 SP16 与 SP1 完全等价。为消除冗余，应直接对比已通过的大形状和实际有效行，结合算法／kernel 及中间值定位差异。能够局部固定计算次序或实现稳定 kernel 时，优先在有效行上表达这项数值规则；不要复制整张训练图来取一行输出。

## 将差异变成小而明确的实现

能由架构配置、参数语义及实际 dtype 确定的行为，据此处理。只有已证实存在且无法统一的参考计算差异，才增加显式参考配置，集中解析并传给相关算子；不根据模型目录名、checkpoint step 或模糊版本标签偷偷选择。默认行为保留已验收路径，配置文档写清参考来源与适用范围。

修复局部舍入后保留旧参考的受影响回归；更换训练参考时也保留两套证据的身份，不能用一个通过结果替换另一个。重复请求／批量重复的位置数与唯一请求数分别报告；旧封存参考的复用不写成新启动参考。

性能评估在实际数值路径上对称预热，使用同一请求、输出预算、调度和缓存初态。单算子或大桶对照解释机制，端到端无 profiler 运行确认收益；[性能对照](benchmarking.md)与[状态生命周期](stateful-inference.md)提供相关边界。
